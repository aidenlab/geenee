A Room’s addresses

A Room is what ties one conversation to its Workspace. Its id is ten letters and digits, and geenee accepts it in either case. Press New Room to open one on the chosen Deployment, the way open_geenee does, or paste an id from a Card.

AddressWhat it showsWho uses it
The Room link. On a computer, the Workspace, with a quiet “Get geenee” link at the right of the tab bar. On a phone, the Workspace hands over to the Hand-off. Guests: it is the link in the Card’s text and QR code.
The Workspace, with no Hand-off on a phone and no Get geenee link. The Organizer: the Card’s Open geenee button and the model use it.
The Hand-off: send the Room link to a computer by email, share sheet or copy. Open it here to see it on a computer. A Guest on a phone, sent from the Room link.
JSON: the Join link of each Viewer, the address the Workspace frames. Opening one shows that Viewer alone in the Room. The Workspace, once as it loads.
JSON: whether each Viewer is connected right now. These are the marks on the Workspace’s tabs. The Workspace, every few seconds while someone looks at it.
Not a page: the WebSocket that tells the Workspace which Viewer a tool call was for. The Workspace, for as long as it is open.

Every one of these but the WebSocket is a use of the Room. A Room expires after a day without use, and then stays expired: these addresses answer with the expired page, or 410 for the JSON ones.

Addresses that need no Room

AddressAnswerWhat it shows
302 geenee’s install address, the one for papers and slides. It redirects to the Marketplace install page, geenee-install.3dg.io/install, from every Deployment.
302 The same redirect, for the old address in Hand-off emails already sent.
200 What this Deployment runs, its tag or branch and commit, and what each Upstream behind it runs.
410 The expired-Room page. geenee never opened this Room, so it counts as expired.
404 The page for a Room link whose id is malformed.
200 The Workspace with no Room, which says to open geenee from a conversation.
405 The Connector address. Hosts POST to it; a browser’s GET is refused.
200 The page review: every page of the Guest flow, the Card included, at phone and computer size. npm run pages; local only.

Behind geenee: the Upstreams and Viewers


geenee forwards each tool call to the Upstream that owns it. Each Upstream serves its own Viewer page, and the Workspace frames those pages. prod geenee uses only the prod ones, and dev geenee and local development use the dev ones.

An Upstream has no page of its own: its /mcp is a working Connector in its own right, and geenee’s /versions asks each one what it runs. A Join link is a Viewer page with ?room=<Room id>. The Workspace adds &embedded so that the Viewer leaves out what the Workspace supplies.



Tricks worth knowing


    
  
  • See the phone flow on a computer. In Chrome’s developer tools, turn on the device toolbar (⌘⇧M), choose a phone, and reload the Room link: it goes on to the Hand-off. A phone is told apart by touch and screen size, never by browser name.
    • 
  
  • “Open here anyway” on the Hand-off uses the /?room= link, because that link never hands over to the Hand-off.
    • 
  
  • Keep a Room alive by leaving its Workspace open in a visible tab: the /connections check every few seconds counts as a use.
    • 
  
  • The case of a Room id does not matter, and nothing from a malformed link is ever shown back on the page.
    • 
  
  • Local development runs the Worker and the Workspace on localhost:5173 (npm run dev) against the dev Upstreams. A Host on the internet cannot reach it without a tunnel; Claude Code on this machine can.
